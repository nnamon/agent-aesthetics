Birdhouse — DEF CON Quals 2026

By steady-engine · Apr 6, 2026 · 12 min read · ren64microcode
"Build a house to my liking to receive the flag."

In this challenge, we are given a tarball containing a single Nintendo 64 ROM. Let's start off by checking what we're dealing with.

BASH
$ ls -la birdhouse/
-rw-r--r--  game-2e437bf8b96a6b58729ceb6c0f09421de505ff8d8f73c1f037557f2289680328.tar.gz
-rw-r--r--  game.z64

$ file game.z64
game.z64: data

$ xxd -s 0x20 -l 32 game.z64
00000020: 4354 4620 426c 6f63 6b20 4761 6d65 0000  CTF Block Game..

A big-endian .z64 ROM with the title "CTF Block Game" baked into the header. Standard libdragon homebrew layout — the cart magic 80 37 12 40 is at offset 0, and bytes 0x20–0x33 hold the title.

Reading the ROM layout

Libdragon uses a "ROMpak" — a small TOC immediately after the IPL3 boot stub that names each section of the cart. The TOC is at file offset 0x1930:

JSON
{
  "branch": "preview",
  "hash": "3c1f25a3ee7c1c4a76e37156764226a499af3653",
  "commit-date": "2026-04-06",
  "dirty": true
}

The "dirty": true is interesting — the libdragon preview tree has been locally modified. That's where the challenge logic lives. Let's pull the code section out.

Booting it

mupen64plus won't run libdragon-preview homebrew — the game ships custom RSP microcode (rsp_tiny3d_clipping) and calls check_emulation() early, which aborts on emulators missing MI repeat mode. The clean path is ares, which is cycle-accurate enough and bundles a GDB Remote Serial Protocol stub.

Pulling the dialogue from RAM

The strings in the binary are partly compressed by libdragon's n64sym dedup scheme. Easiest path: dump the dynamic strings region from a running game and look at what stages the critic walks through.

  1. Begin with a tasteful foundation.
  2. The proportions are nearly acceptable.
  3. Charming, in the way a shed can be charming.
  4. I want rustic elegance, not municipal storage annex.

Six dialogue stages plus the opener. The block name table sits just after:

  • Air, Grass, Dirt, Stone, Wood, Leaves, Sand, Brick

Eight block IDs — Air=0 is the default for an empty cell.

Solving the CSP

The constraint table at 0x80057CA0 defines a CSP over 933 variables, each in {1..7}. Brute-forcing the 7-tuple of reference positions over 7^7 = 823,543 assignments yields exactly one consistent assignment:

PositionX, Y, ZBlock
0x285220, 2, 182 → Dirt
0x2A5321, 2, 196 → Sand
0x2C4922, 2, 93 → Stone
0x32C725, 6, 74 → Wood
0x365627, 2, 221 → Grass
0x386C28, 3, 127 → Brick
0x398D28,12, 135 → Leaves

Recap

The whole challenge is one big graph-coloring CSP solved in 512 bytes of RSP microcode. The theme — r5p_gr4ph_c0l0r_0n_n64 — tells you exactly what category of problem you've just solved.
